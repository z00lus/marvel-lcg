# Headless MCP player

Ronin Edition exposes a small authenticated JSON API for an autonomous solo
player. The API drives the existing controller and rules engine directly. It
does not load HTML, inspect the DOM, or use WebSockets.

## Install in Codex

Start the game server on its usual port, then run:

```bash
./run.sh
python3 tools/install_marvel_lcg_codex.py
```

For a server on another machine:

```bash
python3 tools/install_marvel_lcg_codex.py \
  --server-url http://SERVER_IP:2345
```

Use `--password` only when the server has a configured password. Restart Codex
once after installation so it discovers the `marvel_lcg` MCP server and the
`marvel-lcg-player` skill.

The repository-scoped skill lives in
`.agents/skills/marvel-lcg-player/` and is discovered automatically when Codex
is opened in this repository or one of its subdirectories. The installer does
not copy it into a user directory; it only registers
`tools/marvel_lcg_mcp.py` as a stdio MCP server. Rerun the installer if the
repository is moved to a different filesystem path.

## Engine API

All endpoints are `POST` requests and use the server's existing authentication
middleware:

- `/api/agent/catalog`
- `/api/agent/start`
- `/api/agent/continue`
- `/api/agent/connect`
- `/api/agent/observe`
- `/api/agent/act`
- `/api/agent/save-replay`
- `/api/agent/disconnect`

`observe` returns the current board descriptor, recent rules log, and the exact
legal prompt generated by the normal game controller. `act` accepts one current
effect ID, target object IDs, and resource-effect IDs. Every action must include
the prompt revision, so a delayed agent cannot accidentally answer a newer
decision.

The MCP presents this API as eight compact tools: `catalog`, `start_game`,
`continue_game`, `observe`, `act`, `skip`, `save_replay`, and `disconnect`.
Starting a game always creates a one-hero Rules Reference 1.8 session and
replaces the previous active game, just like Quick Game.

`start_game`, `continue_game`, `act`, and `skip` normally return the next stable
decision in the same call. Their two-second wait is only a maximum deadline;
headless rules resolution usually returns in milliseconds. `observe` is needed
only when an unusually long forced-effect chain returns a transient `running`
state. Do not put a fixed 30-second output wait around individual MCP calls.

## Scope and safety

- The headless player is player 0 and is intended for the fork's solo workflow.
- Decisions still pass through `DeviceManager.WhenInput`; targets, costs,
  timing, replay recording, autosave, and undo use the same engine path as the
  browser client.
- MCP games are excluded from game history, aggregate statistics, ratings, and
  achievements. Their explicitly saved replay is retained for analysis but is
  marked ineligible for future statistics imports.
- Only catalogued content IDs are accepted. Path separators and arbitrary file
  paths are rejected.
- The server is not hardened for public Internet exposure. Keep it on localhost
  or a trusted LAN and configure a password when appropriate.
